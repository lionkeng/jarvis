Jarvis Voice Visualization architecture note

Audio is the clock.

Jarvis is a browser visualization library with a small Bun session service. The browser takes one grant from the service, then speaks directly with a provider. OpenAI runs over WebRTC with an SDP exchange. Gemini runs over a WebSocket with an ephemeral token. A held GET /session stream ties either voice connection to the service’s lifetime. Agent audio drives the visualization; transcript text updates independently.

ArchitectureMap boundaries

The API key stops at the BFF.

The public packages own browser behavior. The server is a Backend for Frontend (BFF): a small backend written for this browser client, not a general-purpose API. It owns the long-lived provider keys. For OpenAI it exchanges the browser SDP offer with POST /v1/live/sessions and returns a session ID and SDP answer. For Gemini it mints a single-use ephemeral token and returns an endpoint, a token, the locked setup, and an expiry. It mints a fresh token for every Gemini reconnect. The browser then exchanges microphone audio, agent audio, and provider events directly with the provider. Microsoft documents the Backends for Frontends pattern in more detail.

Solid cyan lines stay inside the application. The amber dashed link is provider and network work. Its timing varies by network, browser permissions, ICE negotiation, model processing, voice generation, and playout. The page does not claim an end-to-end latency.

ONE HANDSHAKE

The lease names the protocols

The browser opens GET /session first. That stream is the lease. Its ready event lists the protocol ids the BFF holds keys for, such as {"protocols":["openai-live","gemini-live"]}. An older broker that sends {} means openai-live. The following POST /session carries a flat body with an optional protocol. A body with sdp and no protocol stays an OpenAI request.

TWO GRANTS

Each protocol gets its own grant

The OpenAI grant keeps its shape, { session, transport }, with the session ID and the SDP answer. The Gemini grant is { kind: "websocket-token", endpoint, token, setup, expiresAt }. The browser opens the Gemini socket to Google itself, so the BFF never sees conversation audio, transcripts, or tool calls on either protocol.

The workspace keeps the library independent of React and custom elements. The demo is a host application. The server is a separate private BFF.

PUBLIC LIBRARY

Core owns behavior

packages/core/src/voice-viz.ts mounts the canvas, routes normalized realtime events, owns the state machine, attaches remote audio, and runs the per-frame loop.

PRIVATE SERVICE

The BFF owns the secrets

server/src/routes/session.ts checks request method and origin, applies in-memory limits, parses preferences and the optional protocol, then exchanges the SDP offer with OpenAI or mints a Gemini token. The same route serves the GET lifetime stream to allowed origins only, capped per origin by LIFETIME_STREAMS_PER_ORIGIN, and lists its configured protocols on that stream's ready event.

Module ownership

Each module owns one piece of the path.

packages/core/src/transport/broker.ts

Owns the lease. It opens the GET stream, reads the ready payload into a protocol plan, watches for 15 seconds without data, and guards the POST that fetches the grant. It also parses both grant shapes, the OpenAI SDP answer and the Gemini WebSocket token.

packages/core/src/transport/live-transport.ts

Selects the channel and owns the session lifecycle. A host that pins nothing runs the first planned protocol that can run in that browser. createLiveTransport({ protocol }) pins openai-live or gemini-live. Each channel owns its own close discipline behind close(), and abort() releases it at once on lease loss.

packages/core/src/transport/openai.ts

Runs the OpenAI WebRTC channel. It captures microphone media, exchanges gathered SDP through the BFF, waits for Live readiness, and owns each session’s peer, channel, timers, and media cleanup. Its close sends session.close and waits up to 15 seconds for session.closed. Losing the lease immediately stops local media and WebRTC. Provider errors and failed backend responses are reported as events and leave the session open; only session.closed, peer loss, or lease loss end it.

packages/core/src/transport/gemini.ts

Runs the Gemini WebSocket channel against Google. It sends the locked setup, maps tool calls and transcripts to normalized events, and clears queued playback when Google reports an interruption. A goAway message and an unexpected close are both routine: the channel takes a fresh grant, redials with the new token and the latest resumption handle, and emits no disconnected event. Its close stops capture and closes the socket, with a 2 second fallback.

packages/core/src/audio/pcm-duplex.ts

Carries 16-bit PCM for the Gemini channel. It captures at 16 kHz through an audio worklet and plays at 24 kHz into a MediaStreamAudioDestinationNode. That sink never connects to the speakers, so the monitored stream plays once. A browser that refuses a 16 kHz capture context falls back to the device rate.

packages/core/src/state/state-machine.ts

Maps realtime events to idle, listening, thinking, speaking, interrupted, and error.

packages/core/src/audio/media-stream-analyser.ts

Connects the remote stream to Web Audio. Its analyser produces byte frequency and waveform buffers for the feature extractor.

packages/core/src/audio/speech-features.ts

Turns the raw buffers into VoiceFeatures. The values are level, onset, silence duration, spectral centroid, voiced confidence, frequency bytes, and waveform bytes.

packages/core/src/render/canvas-renderer.ts

Owns requestAnimationFrame, resize handling, a capped device pixel ratio, a capped frame delta, canvas clearing, visual clipping, and ordered preset painting.

packages/core/src/render/registry.ts

Maps preset names to painters. The five shipped layers are bars, waveform, ring, particles, and hud.

packages/core/src/text/audio-text-sync.ts

Queues simulation and custom audio-synchronized transcript chunks and releases stable words or CJK graphemes as audible time earns character credit. Live captions use the transcript store’s canonical text directly.

packages/core/src/text/streaming-panel.ts

Builds and paints the on-canvas Pretext text panel. The panel preserves timed chunks so text motion can react to arrival time and audio features.

packages/core/src/transcript/store.ts

Keeps an in-memory snapshot of user and agent messages. Consumer adapters read this store for an accessible transcript outside the canvas.

server/src/providers/openai-session.ts

Builds the provider session policy. It selects gpt-live-1, marin, a gpt-5.6-luna Responses backend, backend output limits, conversational pacing instructions, tool_choice auto, parallel_tool_calls false, and the exact perform_ui_actions grammar.

server/src/providers/gemini-session.ts

Mints one single-use ephemeral token per Gemini connection. The token expires after 30 minutes and has 1 minute to start a session. A field mask names every locked setup field: the model, audio output with one fixed voice, the system instruction, the tools, both transcription fields, and sliding-window context compression. sessionResumption stays outside the mask, so the browser can send its handle.

server/src/providers/demo-agent-policy.ts

Holds one canonical action grammar and two renderers. The OpenAI rendering returns the voice instructions, the backend instructions, and the tool JSON. The Gemini rendering returns one system instruction and flattened functionDeclarations with no delegation wording.

ConversationSequence timing

A conversation crosses the BFF once, then stays peer to peer.

The session request is an HTTP boundary. The live conversation is a WebRTC boundary on OpenAI and a WebSocket boundary on Gemini. The diagram below traces the OpenAI lane. Orange regions show variable time that belongs to the network, provider, or browser. Fixed values below are local constants in the repository. For the overloaded word "session", SDP exchange, and when the live call ends, read What is a session.

The 20 second timer waits for session.started after applying the SDP answer. ICE gathering has a 10 second timeout and the browser broker request a 25 second timeout. It is not a performance promise. The provider round trips and remote playout above are variable by design.

01 · request
The browser posts gathered SDP and preferences.
packages/core/src/transport/openai.ts sends sdp, responseTiming and speechRate to the configured endpoint.
Network timing is variable.
02 · create
The BFF validates and creates the session.
server/src/routes/session.ts allows configured origins. If that list includes a loopback origin, other local loopback origins are also allowed. It then checks rate and session budgets and calls the provider endpoint with the protected key. The GET lifetime stream needs the same allowed origin and counts against LIFETIME_STREAMS_PER_ORIGIN.
Network and provider timing are variable.
03 · connect
The browser negotiates media.
The transport captures microphone audio, opens oai-events, posts the gathered SDP offer through the BFF, accepts the SDP answer, and waits for session.started.
20,000 ms local connection timeout.
04 · listen
Provider events set state.
Live user and assistant captions retain original fragments and timestamps in independent rows. A fragment does not establish a complete turn or audio playback.
Provider transcript and audio timing are variable.
05 · answer
Remote audio starts the visual path.
The incoming track creates an audio element and a MediaStreamAnalyser. Live captions display independently of audio playback. The analyser drives the speaking indicator.
Provider generation and playout timing are variable.
06 · finish
Output silence returns the visual state to idle.
Simulation and custom audio-synchronized events use the text synchronizer. Live uses 350 ms of observed output silence to return the visual speaking indicator to idle.
850 ms local silence tail hold for synchronized text.

The Gemini lane

Steps 01 and 02 are the same. The grant is a token instead of an SDP answer, so step 03 has no media negotiation. The browser opens the WebSocket to Google, sends the locked setup, and treats setupComplete as readiness. Setup has its own 15 second timeout. Captured PCM starts flowing at once, and agent PCM arrives inline on the same socket.

Reconnect every ten minutes

Google closes each Gemini connection after about 10 minutes. Google's documentation describes a goAway message before the close. In live runs the connection closed with code 1011 and no goAway. The channel reconnects on either signal. It takes a fresh grant from the broker, dials with the new token and the latest resumption handle, keeps the same agent audio stream, and emits no disconnected event. Pending tool calls are dropped across the reconnect. Each grant expires 30 minutes after the mint, and the expiry timer follows the newest grant.

When the channel fails closed

Five cases end the session with an error instead of reconnecting. No resumable handle exists. The close code is 1007 or 1008. The new grant fails, which includes a 429 from the broker. The dial fails. A reconnected socket closes within 10 seconds of its own setup, which stops a reconnect loop.

State machine

Live speech follows the received audio track.

The sequence below describes simulation and custom turn-based transports. Both live protocols track output speech through the analyser instead. GPT-Live permits overlapping caption rows, and Gemini streams audio-paced text with no timestamps. packages/core/src/state/state-machine.ts keeps the semantic session state small. The renderer receives that state with the audio features, but no canvas preset decides session state from a visual threshold.

idle→ connect or connected →idle→ user-speech-started →listening→ user-speech-stopped →thinking→ agent-audio-started →speaking→ response-done →idle

Interruption

In simulation, if a user starts speaking while the state is speaking, the machine enters interrupted. Live captions never trigger that interruption path. packages/core/src/voice-viz.ts interrupts queued text and marks the agent transcript message interrupted. A Live disconnect completes the last caption row instead.

Failure and disconnect

A transport error enters error. A provider error or a failed backend response is reported through providererror or backendfailed and leaves the session open. An OpenAI disconnect stops the microphone at once, sends session.close, and keeps the peer connection until session.closed, or a 15 second fallback. Final usage is delivered through the usage event. Lost connections and timeouts report unconfirmed usage. A Gemini disconnect stops capture and closes the socket, with a 2 second fallback and no wait for a provider message. Gemini emits no providererror, backendfailed, or usage event. Losing the lease ends either protocol at once. Cleanup preserves the error until a new connection starts.

UI command path

UI commands use Responses delegation.

The BFF declares perform_ui_actions in the Responses backend at OpenAI session creation, and in the locked setup at Gemini token mint. Once the live connection starts, the BFF does not receive or execute tool calls on either protocol. The provider sends a finalized function call to the browser. Core normalizes it. VoiceViz re-emits it. The OpenAI channel collects response.output_item.done calls within response.event envelopes and waits for response.completed before dispatching them. The Gemini channel dispatches each toolCall message as it arrives. The demo parses each call, runs an XState actor, and returns one structured result on the same live connection. Backend response text never becomes spoken captions.

Amber dashed arrows are provider events on the existing WebRTC data channel. Cyan arrows stay inside the application. Pointer and keyboard requests share the actor and skip the result port.

ready→ dequeue →validating→ parse →executing→ capabilities →reporting→ one result →ready

Two machines, two jobs

Input transcription fills the transcript store. Model function selection emits perform_ui_actions. The voice-session machine still uses idle, listening, thinking, speaking, interrupted, and error. The demo actor uses ready, validating, executing, and reporting. Simulation uses a normalized response-done event to return to idle. Live uses output-audio activity; backend completion does not end speech or the voice session.

Bounds and exactly-once reporting

The FIFO queue holds eight requests. Completed call IDs keep the last 64. Duplicate call IDs are ignored. Execution is ordered, one command at a time, with a 2,000 ms wait for a target to register. Cancellation stops remaining work and lists already applied effects. The actor submits one result per accepted voice call. The result is the call ID and the serialized outcome JSON. The simulation transport reads ok, code, and message from that JSON to choose its spoken line. Live leaves acknowledgement to the session prompts.

packages/core/src/transport/types.ts

Defines provider-neutral RealtimeToolCall and RealtimeToolResult. A result is the call ID and the output JSON. Custom transports must implement submitToolResult and emit disconnected when their disconnect() completes.

apps/demo/src/voice/interaction-contract.ts

apps/demo/src/voice/interaction-machine.ts

apps/demo/src/voice/capability-registry.ts

apps/demo/src/voice/hash-router.ts

apps/demo/src/voice/VoiceApp.tsx

FramePipeline requestAnimationFrame

Every frame samples sound before it paints a layer.

The renderer does not receive raw provider events. Each animation frame receives a compact VizFrame with state, state age, VoiceFeatures, regions, theme, reduced-motion status, and a capped delta time.

Measure the mount

CanvasRenderer uses ResizeObserver. The canvas uses a device pixel ratio capped at 2 to avoid runaway backing-store size.

Choose the source

VoiceViz samples the remote MediaStreamAnalyser, a supplied feature source, or the idle source in that order.

Extract VoiceFeatures

The analyser uses FFT size 2048 and smoothing 0.78. The extractor computes smoothed level, onset, silence milliseconds, centroid, voiced confidence, and preserves the byte buffers for painters.

Lay out regions

computeRegions places the panel at the side only when auto placement sees width at least 640 and a wide enough host. Otherwise it puts the panel at the bottom.

Paint in layer order

The registry creates named presets. The renderer sorts them by layer, clips them to the visualization region, paints them, and then paints the text panel.

Frame safety. CanvasRenderer caps its delta at 100 ms. That prevents a long tab pause from producing one huge particle update or animation jump.

Audio-paced transcript

Text waits for audible speech.

Provider transcript deltas and remote playout do not share a timestamp. AudioTextSynchronizer therefore treats detected remote speech as the local clock. It gives text a small initial credit, then adds credit in proportion to audible time.

PACE

18 characters per second

The base pace is 18 chars/s. The application can multiply that pace through setTranscriptPace.

TAIL

850 ms silence hold

Once source text is done and audio falls silent, the queue waits 850 ms before it flushes any remainder.

FALLBACK

5 second startup timeout

If text completes but audible audio never starts, the queue flushes after 5,000 ms.

Stable chunks

English-like text releases complete whitespace-terminated words. CJK text releases graphemes as they arrive. The panel batches CJK layout at four graphemes to avoid relayout for every character.

Credit cap

Each tick adds only a delta capped at 250 ms. Credit also has a bounded ceiling. A stalled animation frame cannot make the transcript jump far ahead.

The text panel is visual. packages/react/src/transcript-view.tsx offers the accessible React transcript view from the same store.

Demo transport

Simulation uses the same events with fixed delays.

apps/demo/src/demo-transport.ts implements the same transport shape as the live client for the visualization lab. apps/demo/src/voice/voice-demo-transport.ts does the same for the voice-first app, including tool-call parity. Neither models network or provider latency.

Lab turn schedule

The first synthetic user turn begins after 180 ms. Synthetic speech lasts 650 ms. The agent starts streaming after a further 460 ms. Word chunks arrive every 135 ms, and the next turn starts after 1,600 ms.

Synthetic signal

DemoVoiceFeatureSource writes deterministic-shaped frequency and waveform arrays. It reports a low idle signal. During agent speech, it varies level, onset, centroid, and waveform phase so the same canvas path remains active.

Voice-first scripts

Each UI script emits speech boundaries, user text, and one normalized tool-call with a unique call ID. Ordinary Q&A emits an assistant response with no tool call and leaves UI state unchanged. Simulation does not measure live model routing.

Result acknowledgement

submitToolResult records the matching call ID and reads the output JSON. An ok result streams its message. A cancelled result stays silent. Other failures stream a failure line. Live submits all function outputs with response.item.create and sends one bare response.create to continue backend work, including cancellation results. Session prompts request brief success acknowledgements and quiet cancellation; they cannot enforce speech timing.

Operational notes

A few boundaries are easy to miss.

The BFF has no application authentication

Origin checks and in-memory budgets constrain the demo service. They do not identify users. Production deployments need application authentication and durable, shared limits if multiple instances run.

The BFF keeps no conversation data

The server retains only in-memory origin rate-limit, session-budget, and lifetime-stream counters. It does not record Live session IDs, so a server shutdown ends a voice session only through the browser's lifetime stream. The transcript store lives in the browser process for the mounted visualization.

Remote audio is deliberately attached

VoiceViz creates a muted autoplay audio element for the remote stream and also connects the analyser to the audio context destination. The analyser has a monitor option for direct use.

Check the environment variable name

server/src/config.ts reads PORT and defaults to 3010. server/.env.example uses the same PORT name.

Provider policy is server-owned

openai-session.ts sets the output voice marin and sends the model IDs that config.ts reads from OPENAI_LIVE_MODEL and OPENAI_LIVE_BACKEND_MODEL. Live manages context automatically and matches the user language through conversation instructions. The browser sends response timing and speech rate, but it never receives the standard API key. The same request also declares perform_ui_actions with exact action variants. Tool calls still travel browser to OpenAI, not through the BFF.

Custom elements isolate their own CSS

VoiceVizElement mounts inside an open Shadow DOM root. The internal canvas and styles do not inherit a host page's global canvas styling.

The data channel must be open

submitToolResult throws when the Live data channel is missing or not open. The interaction actor treats that as a reporting failure rather than dropping the result silently.

Disconnect can beat the result

If the session disconnects before the actor sends the function output, remaining actions stop and the app records that reporting could not complete. Reconnect starts a fresh session. Do not switch sources while voice work is pending.

Gemini reasoning is a model id

config.ts reads GEMINI_LIVE_MODEL as gemini-3.8-live or gemini-3.8-live-extended-thinking and defaults to the first. There is no GEMINI_LIVE_BACKEND_MODEL. Setting it stops startup, because Gemini Live has no delegation protocol.

LIVE_PROVIDERS must match the keys

At least one of OPENAI_API_KEY and GEMINI_API_KEY is required, so a Gemini-only BFF needs no OpenAI key. LIVE_PROVIDERS orders the keyed providers on the lease, and the first entry wins when a host pins no protocol. An unknown, repeated, or unkeyed entry stops startup.

The Gemini token is locked

gemini-session.ts mints a single-use token whose field mask names the model and every locked setup field. The browser cannot change the tools, the system instruction, the voice, or transcription. It can set sessionResumption, which carries the handle. The token lasts 30 minutes and must start a session within 1 minute.

A Gemini reconnect costs a session slot

A single-use token cannot open a second connection, so each reconnect posts to /session again. That POST passes the origin guard, the rate limit, and the session budget, and spends one slot of each. Size SESSION_BUDGET_REQUESTS for roughly one reconnect every 10 minutes per live session. A 429 from the broker fails the reconnect and ends the session.

Gemini audio plays exactly once

PcmDuplex plays agent PCM into a MediaStreamAudioDestinationNode and never connects that graph to the speakers. VoiceViz monitors the resulting stream like any other agent track. Connecting the playback context to its destination would double the audio.
