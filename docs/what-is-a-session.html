What is a session

In Jarvis the word "session" names three different lifetimes. People mix up the short mint HTTP call, the live WebRTC peer connection, and the UI turn state that resets on every answer. Those are not the same thing.

Overloaded word

Three meanings of "session"

When someone says "the session ended", ask which lifetime they mean. Jarvis uses the same English word for a mint request, a live Realtime call, and a voice UI turn.

01 · MINT

HTTP mint request

POST /session asks the Bun BFF for an ephemeral OpenAI Realtime client secret (ek_*). That "session" ends when the HTTP response returns. The route lives in server/src/routes/session.ts. The provider mint lives in server/src/providers/openai-session.ts.

02 · LIVE CALL

WebRTC Realtime call

After the secret arrives, the browser opens a peer connection to OpenAI. Microphone audio, remote agent audio, and the oai-events data channel share that one connection. Many speak, think, and answer turns can run on it. Transport code lives in packages/core/src/transport/openai.ts.

03 · UI STATE

Voice UI state machine

Core tracks idle, listening, thinking, speaking, interrupted, and error in packages/core/src/state/state-machine.ts. A response.done event returns the machine to idle so the next turn can start. That return to idle is not a teardown of the WebRTC call.

idle→ listen → listening→ stop → thinking→ audio → speaking→ response.done → idle

One live call can walk that loop many times. The peer connection stays up while the UI state keeps returning to idle.

Ephemeral client secret

How the secret is used

The BFF holds OPENAI_API_KEY. The browser never sees that key. It sees only a short-lived client secret, and it uses that secret once. The timing diagram above is the same handoff drawn as a sequence.

01 · mint
The BFF mints with the long-lived key.
openai-session.ts posts to https://api.openai.com/v1/realtime/client_secrets with Authorization: Bearer set to OPENAI_API_KEY. The response includes a value field (an ek_* token) and may include expires_at.
02 · connect
The browser spends the secret once.
OpenAIRealtimeTransport posts an SDP offer to https://api.openai.com/v1/realtime/calls with Authorization: Bearer set to that value. That is the only browser use of the ephemeral secret.
03 · live path
After the handshake, the secret is unused.
Mic audio, remote audio, and oai-events travel browser to OpenAI over WebRTC. The BFF is off the live path. It does not relay turns, tool calls, or transcript text.

Connect-time gate only. parseEphemeralSession rejects an already-expired expires_at when it parses the mint response. That check does not close a call that is already connected.

Live call lifetime

When the live call ends

The live Realtime call ends when the peer connection tears down. It does not end when a single answer finishes.

What ends the call

An explicit disconnect() in OpenAIRealtimeTransport closes the data channel, closes the peer connection, and stops local tracks. After the call has connected, a peer connection that becomes closed, disconnected, or failed also tears down and emits disconnected.

What does not end the call

response.done only returns the UI state machine to idle. expires_at is a connect-time gate after parse. Neither event closes an established WebRTC call by itself.

BFF limits

Session budget caps minting, not call length

session.ts applies a per-origin session budget before it asks OpenAI for a client secret. That budget limits how often an origin may mint. It does not limit how long a live WebRTC call may stay open once the secret is spent.
